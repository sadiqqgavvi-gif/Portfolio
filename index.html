CASE STUDY — 01 ★ Flagship · Final Year Project

SmartHire

An AI interview coach that asks real questions and scores real answers — built as my final year project.

ReactNode.jsExpress MongoDBTailwind CSSOpenAI API REST APIJWT Auth
Live Demo View Code
smarrthire.netlify.app

SmartHire is an interview-prep tool built for job seekers getting ready for real technical and behavioral rounds. Most practice tools recycle the same static question bank — SmartHire generates adaptive questions and scores written answers with an LLM in the loop, so practice reflects how you actually answered, not just whether you answered. It covers the full loop: register, run a timed mock session, get scored feedback, and track progress from a personal dashboard.

AI Interview Evaluation

LLM-scored feedback on free-text answers, not keyword matching.

Mock Interview Mode

Timed practice sessions across technical, behavioral and situational tracks.

Large Question Bank

MongoDB-backed question sets spanning multiple interview categories.

Personal Dashboard

Track sessions, scores and progress over time.

Auth & Sessions

JWT-secured accounts with protected practice routes.

Responsive UI

Mobile-first layout built with Tailwind CSS.

Architecture
FrontendReact, Tailwind CSS
BackendNode.js, Express.js
DatabaseMongoDB, Mongoose
AuthJWT
IntegrationOpenAI API
Engineering challenges
Scoring free-text answers consistently — not just checking for keywords — took real prompt design and response parsing.
Keeping AI response latency from breaking the mock-interview flow meant handling loading and error states carefully end to end.
Modeling question banks, sessions and per-user progress in MongoDB so the dashboard stays accurate mid-session.
What I learned

Working with an LLM API in a real product meant designing for uncertainty — prompts fail and responses are inconsistent, so the UI has to handle that gracefully.

This was my first project end to end, from schema design to deployment, and it's where auth, sessions and API design actually clicked.

CASE STUDY — 02 ⚡ Real-time · MERN + Socket.IO

Real-Time Chat Application

A MERN + Socket.IO messenger with live delivery, read receipts and admin-managed groups.

ReactNode.jsExpress MongoDBSocket.IOJWTDocker
View Code
chat-app — localhost

A full-stack messaging platform built with the MERN stack and Socket.IO, supporting one-to-one and group conversations. I built it to go past the usual "send a message, see it appear" chat tutorial — with real delivery and read receipts, typing indicators, live presence, rich media, and admin-managed groups with automatic permission handoff, closer to how a production chat product actually behaves.

Real-Time Messaging

Socket.IO with per-user and per-chat rooms for efficient delivery.

Secure Auth

JWT + bcrypt password hashing, protected routes on both ends.

Delivery & Presence

Read receipts, typing indicators, live online/offline status.

Rich Media

Images, files and in-browser voice notes, plus reply threads.

Group Admin Controls

Server-enforced permissions with automatic admin handoff.

Containerized

Dockerized for a consistent run anywhere.

Architecture
FrontendReact
BackendNode.js, Express.js
DatabaseMongoDB
Real-timeSocket.IO
AuthJWT + bcrypt
DeploymentDocker
Engineering challenges
Routing real-time events through per-user and per-chat Socket.IO rooms without leaking messages between conversations or duplicating deliveries.
Keeping message state in sync across multiple open tabs and devices for the same account.
Designing group permissions so admin rights transfer automatically when an admin leaves — never leaving a group without one.
What I learned

Socket.IO room design and message sync are a different set of problems than typical REST CRUD — I got a lot more comfortable reasoning about state across concurrent connections.

Dockerizing it forced me to think about the app as something that has to run the same way on someone else's machine, not just mine.
